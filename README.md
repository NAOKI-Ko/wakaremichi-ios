# まいにちの分かれ道

Claudeが全面的に書き直したソース一式。ここから先は **Codexが検証・調整・修正を担当** する前提。

---

## 今回の書き直しで直したこと

### 「道が3マス幅に見える」不具合

正しく生成された迷路の通路は必ず1マス幅になる。3マス幅に見えていたのは
**生成ロジックの実装バグ** で、アルゴリズムの必然ではない。

同じアルゴリズムをPythonで先に実装し、30日ぶんのseedで
「2x2の開放ブロック(=太い通路)が1つも生じないこと」「同じseedで完全に同じ迷路になること」
を確認してからSwiftに移植した。

再発検知のため、`Maze.firstWideCorridor()` と `Maze.isGoalReachable()` を用意し、
`RunCoordinator.init` で起動時に自動チェックしている。異常があれば探索画面に
赤い警告が出る(正常なら何も出ない)。**この警告が出たら生成ロジックが壊れている。**

### 51x51 を軽く描くための遅延生成

51x51 = 2601マス。ノードを最初に全部作ると重いので、
**一度でも霧が晴れたマスだけノードを生成** するようにした(`MazeScene.ensureTile`)。
未踏の領域にはノードが存在しない。

## 体験の流れ

1. **初回だけ**: 5体から旅人を1体選ぶ(`@AppStorage` に保存)
2. 「今日はどんな気分?」4択、またはスキップ
3. その日の迷路を探索。ゴール・体力切れ・「ここまでにする」で一時停止する
4. 広告を見てその場から続けるか、「今日はここまで見る」で結果を確定する
5. 「今日の霧は、どうでしたか?」3択、またはスキップ
6. 通常5枚に加え、条件を満たすと「鏡」「心の分かれ道」のカードも横にめくって見る
7. 結果から共有画像を書き出したり、過去の旅のコレクションを見返す
8. 同じ日にもう一度開くと、いきなり保存済みの結果が出る(その日はもう歩けない)

## 設計上、意図して決めたこと

### 移動は「分かれ道で止まる」
一本道は自動で滑走し、曲がり角も自動で曲がり、分かれ道・行き止まり・ゴール・
未開封の宝箱でだけ止まる。1スワイプ = 1つの選択になり、企画名と一致する。

### 51x51 と早抜けはセット
seedごとの振れ幅を計測したところ、**最短7〜21スワイプ、全踏破45〜534スワイプ** と
日によって桁が変わる。早抜けが無いと、運が悪い日に10分近く拘束されてしまう。
「最速なら1分、じっくりなら10分」を成立させるには「ここまでにする」が必須。

### 旅人の対応軸は絶対に見せない
選択画面でラベルを見せると「どう見られたいか」で選ぶことになり、素の直感が出ない。
見た目と佇まいだけで選ばせ、**3日ぶん歩いたあとに答え合わせを見せる**
(`Diagnosis.travelerReflection`)。ここがこのアプリの一番深い「わたしを探す」層。

### 診断のしきい値は全部仮
実プレイのログが1件も無い状態で決めた推測値。特に **柔軟性の式** は
「行き止まりが多い = 色々試している」とも「道を覚えるのが下手」とも取れる、
解釈の分かれる指標。数日ぶん溜まったら分布と軸同士の相関を見て必ず調整すること。

## 実機で触ったフィードバックを受けての変更

「思ったより楽しかった」という一次反応をもらった上での、6つの修正:

1. **歩行速度**: `Tuning.stepDuration` を 0.085→0.13 に。ゆっくりに
2. **足音の音量**: 波形自体の振幅を0.5倍に下げ、他のSEより控えめにした
3. **フレームレート**: タイルの色乗せを `SKShapeNode`(ベクター描画)から
   `SKSpriteNode + colorBlendFactor`(テクスチャ描画)に変更。51x51で
   霧が晴れるたびに大量生成される部分なので、ここが一番効くはず。
   ホタルの数も40→24に削減。**それでも重ければ、Instrumentsで
   GPU/CPUプロファイルを取って原因を特定してほしい**(ここから先は
   実機でないと分からない)
4. **体力(スワイプ上限)**: 歩いたマス数で減り、0になったら
   「ここまでにする」と同じ扱いで自動的に終わる。ゴールに同時到達した
   場合はゴール扱いを優先する。ワープの瞬間移動ぶんは消費しない。
   `Tuning.staminaMax`(既定1000)は、シミュレーションで「ゴールまでの
   実歩数が運によって700〜5000マスと大きく振れる」ことを確認した上での
   仮の数字。**「頻繁に体力切れになる/全く切れない」は実プレイで
   要調整**
5. **ミニマップ**: 霧が晴れた場所(explored)だけを描く。未探索の
   迷路を透かして見せることはない(そこは意図的に守った)
6. **UIレイアウト**: 画面を上70%(ゲーム)/下30%(HUD: 旅人の絵・
   体力ゲージ・ミニマップ)に再構成。`GeometryReader` で比率固定

### ミニマップとHUDの仕組み

`MazeScene` はSwiftUIから直接observeできないため、`onHUDUpdate`
クロージャで移動のたびに `HUDSnapshot` を1つ渡す方式にしている。
`RunCoordinator.hud` がこれを保持し、`ExplorationHUD` が表示する。

## 「もう一度探索する」（広告・体力回復）

ゴール到達・体力切れ・「ここまでにする」のどれで止まっても、即座には
結果を確定しない。一時停止画面を挟み、「続きを歩く（広告）」か
「今日はここまで見る」かを選べる。

- `Tuning.maxReplaysPerDay`（既定2）で1日の再開回数に上限を設ける
- 続きは最初からではなく、位置・霧・軌跡を保ったまま体力だけ満タンに戻す
- ゴールへ一度でも到達した事実は `everReachedGoal` として、その先へ歩いても保持する
- 再開回数は `DailyRun.replayCount` に保存し、診断コメントにも静かに反映する
- `AdProvider.swift` は広告SDKの抽象化だけを用意。現在の `MockAdProvider` は
  1秒待って必ず成功する。SDK決定後は `AdProvider` 準拠型へ差し替える

## 物語「分かれ道の洞窟」の統合

新しい画面を増やしすぎず、既存フローの言葉と結果カードへ物語を重ねる。

- 初回の旅人選択前だけ `PrologueView` を表示し、
  `@AppStorage("hasSeenPrologue")` で再表示を防ぐ
- 一時停止画面の見出しを「灯り」の語彙へ差し替える
- 通算3／7／14／21／30日目は、通常の道しるべに代えて短い物語の断片を表示する
- 通算7日目から、4軸の平均で最も低い軸を「まだ静かなままの道」として示す
  6枚目の「鏡」カードを解放する
- 通算日数は連続日数ではないため、休んでも進捗は失われない

## 「はじめからやり直す」と性格コード

一時停止画面に、位置・霧・軌跡を保つ「続きを歩く」に加えて、今日の探索を
スタート地点へ巻き戻す「はじめからやり直す」を追加した。どちらも広告視聴で
使い、`Tuning.maxReplaysPerDay` の1日ぶんの枠を共有する。

- `MazeGame.resetForRestart()` は位置・霧・軌跡・宝箱・ゴール到達記録・
  診断ログを初期化する。`replayCount` と `restartCount` は、その日の広告利用を
  正しく数えるため維持する
- `MazeScene.restartAfterAd()` は、宝箱を閉じたテクスチャへ戻し、過去に生成した
  タイルへ霧をかけ直し、旅人・光・カメラをスタート地点へ戻す
- `DailyRun.restartCount` に保存し、再起動後の結果でも診断コメントを再構成できる
- `PlayStyleAxes.personalityCode` は新しい測定ではなく、既存4軸を強い順に並べた
  4文字コード。結果画面の傾向カードへ表示する

「はじめから」は結果を選び直す使われ方もあり得るため、利用回数を診断コメントへ
評価せず静かに織り込み、無制限にはしていない。

## 心の分かれ道・コレクション・共有・買い切り

- 迷路生成時、宝箱とワープに使わなかった行き止まりへイベント座標を1つ置く。
  日付seedで選んだ3択を一度だけ表示し、選択中はSpriteKitのヒットテストと
  SwiftUIのスワイプ処理を両方止める。選択は`DailyRun`へ保存して復元する
- イベントのテーマは直近7日と重ならない候補を優先する。候補が尽きた場合だけ
  全6件から選ぶため、常に決定的でクラッシュしない
- コレクションは未購入時に直近7件、購入済みなら全件を表示する
- 共有画像は軌跡・称号・旅人・日付だけを640×800pt／3倍解像度で書き出す
- `StoreManager.removeAdsProductID` の `com.karemichi.removeads` は仮ID。
  App Store Connectで非消耗型製品を作成し、実IDへ差し替えるまでSandbox購入は行えない
- 買い切り済みでは再開・やり直しを広告なしで使え、コレクションの7件制限も解除する

## 検証で見てほしいこと

理屈より身体の反応のほうが正直。

1. 分かれ道で一瞬手が止まるか(考えず連打しているなら分岐の質が足りない)
2. 行き止まりで「うわ」と笑えるか(面倒に感じるなら多すぎる)
3. 軌跡の線画を見て何か言いたくなるか
4. **翌日に自分でアプリを開いたか** ← 唯一の合格ライン
